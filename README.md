# Praxis Board

A local, bird's-eye Kanban dashboard for [Praxis](https://github.com) (`prx`) project-management
workstreams — the `prxwork/` markdown convention used by the `prx-orchestrate` Claude Code skill.

Reads a project's `prxwork/` frontmatter and renders every workstream as a card in a
six-column board (Backlog · Ready · In Progress · Blocked · Done · Dropped), sortable by
artefact ID or name, with panels for open issues by severity and artefacts that have gone
quiet. It's read-only and non-interactive by design — no drag-and-drop, no writes back to
the source project. All board movement still happens through the `prx-*` skills; this is
just a way to see the result at a glance.

## Quick start

```bash
npm install                                        # TypeScript toolchain (devDependencies only)
npm run refresh -- --root /path/to/your/project    # extract prxwork/ into dist/public/data.json
npm start                                          # build, then serve at http://localhost:4173
```

`npm install` is a genuine prerequisite: both `npm start` and `npm run refresh` compile first, and
without `node_modules` they fail on a missing `tsc`.

A snapshot of the LAD project is checked in at `src/public/data.json`, so the board works out of
the box. That file is a seed, not the file the board reads: the build copies it to
`dist/public/data.json` only when that destination is absent, and never overwrites it afterwards.
`npm run refresh` writes straight to `dist/public/data.json`, so refreshed data survives every
later build. Re-run it whenever you want current data.

## How it fits together

```
Praxis-Dashboard/
├── src/                             hand-written source
│   ├── server.ts                    zero-dependency static file server (npm start)
│   ├── scripts/
│   │   └── extract-praxis-data.ts   reads <project>/prxwork/ → writes dist/public/data.json
│   ├── types/
│   │   └── praxis-data.d.ts         shared payload types (both compilations, no imports)
│   └── public/
│       ├── index.html               page shell and markup
│       ├── styles.css               all page styling
│       ├── app.ts                   fetches data.json, renders KPIs, board, panels
│       ├── data.json                committed seed snapshot (copied to dist/ if absent)
│       └── tsconfig.json            browser-side compiler config (DOM, no Node types)
├── tools/
│   └── copy-assets.mjs              copies the non-TS assets and seeds data.json
├── tsconfig.json                    Node-side compiler config (server + extractor)
└── dist/                            generated by npm run build — gitignored
    ├── server.js
    ├── scripts/extract-praxis-data.js
    └── public/                      index.html, styles.css, app.js, data.json
```

`extract-praxis-data.ts` parses each workstream's frontmatter and its linked plans, issue
lists, and task lists directly from the markdown — the same source of truth the `prx-*`
skills and `prx-index.mjs` use. It never writes back to the project it reads.

## Scripts

| Command | Does |
|---|---|
| `npm run build` | Compiles both TypeScript projects into `dist/` and copies the static assets |
| `npm start` | Builds, then serves `dist/public/` at `http://localhost:4173` (override with `PORT=xxxx npm start`) |
| `npm run refresh -- --root <dir>` | Builds, then regenerates `dist/public/data.json` from `<dir>/prxwork/` |

`npm run refresh` accepts `--out <file>` to write somewhere other than `dist/public/data.json`.

## Notes

- There is a TypeScript compile step and two devDependencies (`typescript`, `@types/node`), but
  no runtime dependency, no framework and no bundler — `server.ts` and `app.ts` use only
  Node/browser built-ins, and `tsc` just strips the types.
- There is deliberately no `clean` script. `rm -rf dist` works, but it discards refreshed data:
  the next build reseeds `dist/public/data.json` from the committed demo snapshot, so re-run
  `npm run refresh` afterwards.
- "Needs attention" (artefacts `in-progress` for 14+ days) is computed in the browser
  against the *viewer's* clock from each artefact's own `updated` date, so it stays
  accurate no matter how long ago the data was last refreshed.
- Works with any project that follows the Praxis `prxwork/` convention, not just LAD —
  point `--root` at whichever project you want to inspect.
